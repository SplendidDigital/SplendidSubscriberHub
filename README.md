Splendid Subscriber Hub** is a WordPress plugin designed to help website owners discover, organize, and manage subscriber and contact records across their WordPress websites.

The plugin provides an administrative interface for inspecting WordPress user accounts and potential subscriber data stored in supported database tables. It is designed to help website owners understand where contact records originate, distinguish subscribers from other contacts, and build a centralized subscriber management workflow.

### Key Features

- **Subscriber Discovery:** Scan supported WordPress database tables and identify potential subscriber and contact sources.
- **Contact Directory:** Inspect available contact records and relevant fields from detected sources.
- **Source Classification:** Organize records by their originating database source and contact category.
- **AI-Assisted Classification:** Optional Gemini API integration for supported classification tasks.
- **Custom Subscription Form:** Provide a dedicated subscription form for collecting new subscriber details, subject to configuration and testing.
- **Cross-Website Integration:** Support a planned workflow for securely retrieving aggregate subscriber information from connected WordPress websites.
- **Public Subscriber Counts:** Support integration with website-specific displays of aggregate subscriber counts, where configured.
- **Privacy-Conscious Design:** Separate public aggregate statistics from private contact details and encourage appropriate consent-based subscriber management.

### Intended Use

The plugin is intended for WordPress administrators, publishers, developers, and digital entrepreneurs who want better visibility into subscriber data and a foundation for managing contacts across multiple websites.

### Important Notes

Database discovery identifies potential contact records; it does not automatically prove that a person has subscribed to a newsletter or consented to marketing emails. Comment authors, WordPress users, form submissions, and confirmed email subscribers should be treated as distinct categories.

External subscription services may require separate API integrations. Email confirmation, unsubscribe handling, cross-site connections, and other features should be tested in the target WordPress environment before production use.
